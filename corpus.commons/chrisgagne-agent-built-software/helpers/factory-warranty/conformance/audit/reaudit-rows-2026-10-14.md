## How to read this (copied from the matrix)

- **Subject.** `agent` rows judge the factory itself: its Claude legs (spec, tests, build, Claude reviewer, sort, assessor), its Codex reviewer, builder-command adapters, their tools, briefs, permissions, sandboxing and what they read. `product` rows judge what the factory does for software it builds that has LLM features; a strategy is given to `product` only where the factory has no such surface of its own (vector stores, fine-tuning, inter-agent network protocols, end-user endpoints). Each row has one subject and one status.
- **Ledger checks** are written `stage:check`, e.g. `gate:secrets`, `review:findings:claude`, `build:guard`. `*:leg:*` means the leg event every model leg writes (`spec:leg:spec`, `build:leg:build`, `review:leg:reviewer-codex`, ...), which records the command line (tool list and flags), model, cost or tokens, turns, duration, and hashes of the brief and transcript.
- **Several parts.** A strategy with several required parts is `demonstrated` only when every part is; when some parts are addressed and others are not, it is `asserted` and the note names the missing part; `gap` means nothing addresses the strategy's main ask.
- **Claude-sandbox caveat.** Claude Code's own sandbox is what stops a script a Claude leg writes from writing outside the worktree, reading credential files or reaching the network; the guard reads tool-call text and can't see what a script does. That sandbox is checked only by `tests/test_isolation.py::test_claude_legs_run_in_claude_codes_sandbox_with_the_guard`, which reads the settings file the leg is given, and by one live probe recorded in `REVIEW-2026-10-11.md`. No test shows it stopping an escape. The same boundary under `sandbox-exec` (gate commands, builder-command adapters) is shown by `tests/test_isolation.py`. Rows that rest on Claude Code's sandbox for Claude legs are therefore at most `asserted`. A live escape-probe test on a cheap model would raise most of them.
- **Codex reviewer.** It runs under Codex's own `-s read-only` sandbox, outside the guard and `sandbox-exec`, and can read the whole disk, credential files and the change folder included (DESIGN.md, Isolation, "Not covered, plainly").
- **llm-agent review focus (the product mechanism).** For built software the only LLM-specific mechanism is triage's `llm-agent` risk class (`factory/stages/triage.py`): story keywords (llm, prompt, openai, anthropic, claude, gpt, embeddings, langchain, tool call, mcp, ai agent, agentic), paths `**/prompts/**` and `**/llm/**`, and diff patterns for JS `require`/`import` of `openai` or `@anthropic-ai/sdk` and Python `import openai` or `import anthropic`. It adds a review focus that names both OWASP lists by title plus "prompt injection, excessive agency, tool misuse, data leaking through the model", and a residual-risk line in the pack ("watch it in production"). Reviewers are not given the lists' text. The common Python form `from anthropic import Anthropic` (or `from openai import OpenAI`) matches the pattern as of `bbd2241`. DESIGN "Next 8" (model output in the product checked by code) is not built.
- **Product catches by calibration.** Three fixtures show review blocking LLM-feature defects in the sample app, in each of the none, seeds and distillations runs of 2026-10-11: `05-prompt-injection` (note text moved into the system prompt; a `send_email` tool with a model-chosen recipient: bears on LLM01.1, LLM01.4, LLM01.6, LLM01.8, LLM03.1–LLM03.6, ASI01, ASI02.1), `10-theory-drift` (full model transcripts written to the info log: LLM02.7, LLM02.11) and `09-silent-failure` (a tool reporting "sent" when the send failed: LLM07). `03-committed-secret` shows `gate:secrets` catching an LLM provider key in config. Where those strategies are scored with subject `agent`, the product catches don't change the status.
- **GitHub.** Where a GitHub security feature would close a row or raise it, the note says "GitHub: <feature>". The factory uses none today and nothing is pushed to GitHub, so no status counts them.
- **PROPOSED** marks a fix or value the standards don't supply.
