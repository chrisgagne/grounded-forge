System archetypes are generic, recurring system structures represented as causal loop diagrams. They provide recognizable patterns for anticipating traps, discussing system behavior, generating alternative interventions, and building more detailed models. There is no single definitive catalog.

The source describes five archetypes:

- **Fixes that fail:** A short-term fix reduces a problem but creates an unintended consequence that later makes the original problem worse.
- **Success to the successful:** Two groups compete for resources; the initially more successful group receives more resources and improves further, while the other group enters a downward spiral.
- **Shifting the burden:** A quick response addresses symptoms but diverts capacity from a slower fundamental solution, increasing dependence on the symptomatic fix.
- **Drifting goals:** A gap between desired and actual performance is reduced by lowering the goal instead of taking corrective action to improve performance.
- **Limits to growth:** A reinforcing loop initially drives growth, but a balancing loop created by a limiting condition or resource constraint eventually counteracts further improvement.

Archetypes are diagnostic aids, not prescriptions. Applying a familiar template too quickly can erase important differences between situations, constrain creative modeling, or allow a modeler's technical authority to overshadow participants' lived knowledge.
